# Structure — miRNAseq Analysis Pipeline

## Directory Tree

```
miRNAseq/
├── .git/                        # Git repository metadata (managed by git)
├── .planning/                   # Project planning and architecture docs
│   └── codebase/
│       ├── ARCHITECTURE.md      # System design, data flow, patterns
│       └── STRUCTURE.md         # This file
├── .venv/                       # Python virtual environment (managed by uv)
│   ├── bin/                     # Executables: python, cutadapt, activate scripts
│   └── lib/
│       └── python3.11/
│           └── site-packages/   # Installed packages (biopython, cutadapt, mirge3, etc.)
├── .python-version              # Pins Python version to 3.11 (read by uv/pyenv)
├── README.md                    # Pipeline survey, recommended tools, workflow docs (Korean)
├── main.py                      # Package entry point (stub)
├── pyproject.toml               # Project metadata and dependency declarations
├── setup_wsl.sh                 # WSL environment setup script (empty)
└── uv.lock                      # Locked dependency resolution (managed by uv)
```

## Purpose of Each File

### Source Code

| File | Purpose |
|------|---------|
| `main.py` | The single Python source file and package entry point. Currently a stub (`print("Hello from mirnaseq!")`) with a `main()` function and an `if __name__ == "__main__"` guard. This is where pipeline orchestration logic will be added. |

### Configuration and Environment

| File | Purpose |
|------|---------|
| `pyproject.toml` | PEP 517/518-compliant project configuration. Declares the project name (`mirnaseq`), version (`0.1.0`), Python constraint (`>=3.11`), and all runtime dependencies. This is the authoritative list of direct dependencies. |
| `uv.lock` | Fully resolved, pinned dependency tree generated by `uv`. Contains exact versions and hashes for all packages (direct + transitive) across all supported platforms. Should not be edited by hand. |
| `.python-version` | Single-line file containing `3.11`. Used by `uv` and `pyenv`-compatible tools to automatically select the correct Python interpreter. |
| `setup_wsl.sh` | Bash script intended to configure the WSL (Windows Subsystem for Linux) environment. Currently empty — a placeholder for future environment setup steps such as installing system-level bioinformatics tools. |

### Documentation

| File | Purpose |
|------|---------|
| `README.md` | Comprehensive pipeline planning document written in Korean. Compares available smRNA-seq pipelines (nf-core/smrnaseq, miRDeep2, miRge3.0, sRNAbench, Chimira, OASIS2), recommends two pipeline options (Nextflow-based and custom Python/R), outlines the full analysis workflow, and lists required reference data and external resources. |

### Planning

| File | Purpose |
|------|---------|
| `.planning/codebase/ARCHITECTURE.md` | System architecture document: design patterns, data flow, entry points, component interactions, dependency roles. |
| `.planning/codebase/STRUCTURE.md` | Directory structure document (this file): layout, file purposes, naming conventions, key locations. |

### Environment (Managed, Not Hand-Edited)

| Path | Purpose |
|------|---------|
| `.venv/` | Python virtual environment created and managed by `uv`. Contains the Python interpreter and all installed packages. Not committed to git. |
| `.git/` | Git object store and metadata. Managed exclusively by git. |

## File Naming Conventions

### Current Conventions (Observed)

- **Python source files**: lowercase with underscores (`main.py`). The project name itself (`mirnaseq`) follows this convention in `pyproject.toml`.
- **Shell scripts**: lowercase with underscores, `.sh` extension (`setup_wsl.sh`).
- **Documentation**: `SCREAMING_SNAKE_CASE.md` for planning documents (`ARCHITECTURE.md`, `STRUCTURE.md`); standard title-case for the project README (`README.md`).
- **Configuration files**: Standard tool-specific names (`.python-version`, `pyproject.toml`, `uv.lock`).
- **Hidden directories**: Leading dot for tooling and metadata (`.git/`, `.venv/`, `.planning/`).

### Recommended Conventions for Future Development

- New Python modules: `lowercase_underscore.py` (e.g., `preprocessing.py`, `alignment.py`, `differential_expression.py`)
- Test files: `test_<module_name>.py` placed in a `tests/` directory
- Configuration files for pipeline runs: `config/` directory with TOML or YAML format
- Input/output data: `data/raw/`, `data/processed/`, `results/` (not committed to git; add to `.gitignore`)
- Reference data: `reference/` directory (not committed to git)

## Notes on the Current State

The repository is at an **early scaffold stage**. The environment is fully configured and reproducible (uv + lock file + Python version pin), but no domain-specific pipeline code has been written beyond the entry-point stub. The `README.md` serves as the primary design document and decision log for pipeline tool selection. The `setup_wsl.sh` is a placeholder for system-level dependency installation steps that will be needed before the Python pipeline can call external CLI tools (Bowtie, miRDeep2, etc.).
